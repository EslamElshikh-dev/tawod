## طريقة التشغيل محليًا

يتطلب المشروع Node.js 20.9 أو أحدث.

### تثبيت الحزم وتشغيل بيئة التطوير

```bash
npm ci
npm run dev
```

### إنشاء نسخة الإنتاج

```bash
npm run build
```

ينشئ الأمر مجلد `out/`، ثم يتحقق آليًا من التطابق الحرفي لجميع صفحات HTML وعددها 176 صفحة ومن وجود الأصول الأساسية.

---

## النشر على GitHub Pages

المشروع مناسب للنشر على Vercel أو GitHub Pages من مجلد `out/`.

### خطوات مقترحة

1. شغّل `npm ci`.
2. شغّل `npm run build`.
3. ارفع محتويات مجلد `out/`، ويتضمن ملف `CNAME` بالقيمة:

```text
tawodco.com
```

4. سير العمل `.github/workflows/deploy-pages.yml` ينفذ هذه الخطوات تلقائيًا بعد الدمج المعتمد في `main`.
5. بعد النشر، اختبر الموقع والروابط وملف السايت ماب.

## استراتيجية الانتقال إلى Next.js

- ملفات HTML الحالية هي مصدر المحتوى المعتمد في هذه المرحلة.
- Route Handlers ثابتة تولّد المسارات أثناء البناء عبر `generateStaticParams`.
- الأصول تُجهز في `public/` وقت البناء فقط، لذلك لا توجد نسخ مكررة داخل Git.
- اختبار `verify-next-export.mjs` يمنع اعتماد أي بناء يغيّر الصفحة أو يفقد مسارًا.
- يمكن لاحقًا تحويل الصفحات إلى React Components تدريجيًا، صفحة أو مجموعة صفحات في كل مرة، دون تغيير الروابط الحالية.

## إرشادات الصيانة

- عند إضافة صفحة جديدة، يجب إضافتها إلى `sitemap.xml`.
- عند تغيير رابط صفحة، يجب تحديث جميع الروابط الداخلية المرتبطة بها.
- عند إضافة صورة جديدة، يفضل استخدام WebP مع اسم ملف وصفي باللغة الإنجليزية.
- يجب كتابة Alt Text واضح للصور المهمة.
- يفضل الحفاظ على نفس نظام الألوان والخطوط والهوية البصرية.
- لا يتم حذف صفحات قديمة مؤرشفة بدون خطة Redirect مناسبة.
- يجب مراجعة تجربة الجوال بعد أي تعديل في الهيدر، الفوتر، الكروت، أو أزرار التواصل.
